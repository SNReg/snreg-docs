# 0002: UEID entity identifiers

**Status:** Accepted

## Context
The same entities show up in URLs, the audit log, events, split-screen links and the agent protocol. Bare integers or UUIDs don't say what kind of thing they point at.

## Decision
Every entity ID is `<prefix>_<ULID>`, e.g. `usr_01J8Z3Q4X5N6M7P8R9S0T1V2W3`.
- The prefix (2 to 3 lowercase letters: `usr`, `grp`, `dev`, `ast`, `tkt`, …) names the entity kind.
- The ULID is canonical uppercase Crockford base32, so IDs sort by creation time.
- It's stored as `text` with `CHECK (id ~ '^[a-z]{2,3}_[0-7][0-9A-HJKMNP-TV-Z]{25}$')`.
- Only the canonical spelling parses, so one ID can't be stored two ways.

The implementation is the `snreg-ueid` crate in `snreg-core`.

## Consequences
- Any ID can be routed to the right record without a lookup.
- IDs are 30 to 32 characters. That's larger than a UUID column, which is acceptable at this scale.
